# Seamlet SDK

The rules of this project for agents and humans. The development process is set by Cyberzavod: stages, roles, and general principles come from its harness, and here is only what belongs to the project. The files for a specific agent (for example, `CLAUDE.md`) are created by `npx cyberzavod sync` on top of this file.

## About the project

What a site installs to be edited in the Seamlet CMS. The CMS (a separate, closed product) stores content, signs people in and publishes; this repository holds only what runs on a site, and it is public.

- TypeScript, strict (`astro/tsconfigs/strict` plus `noUncheckedIndexedAccess`, `noUnusedLocals`, `noUnusedParameters`). ESLint with `strictTypeChecked` and an exhaustive `switch` over a union; Prettier with `prettier-plugin-astro`; Vitest, with jsdom for the DOM (`// @vitest-environment jsdom`); tsup builds the package. Node 24+, npm workspaces.
- Everything is in English: code, comments, messages, tests, commits, documentation. Texts a site's visitor or the CMS's user reads are in Russian.

## Architecture

- `packages/astro` — `@seamlet/astro`, published to npm.
  - `src/schema` — the schema language, the one description of content: field kinds (`text`, `richText`, `number`, `date`, `time`, `image`, `link`, `url`, `toggle`, `choice`, `choices`, `reference`, `references`, `group`, `collection`) and their builders, `ContentOf`, `defaultContent`, `parseContent` (brings any input to the shape of a schema, with issues by field path), `editable<Content>()` (the typed marker `data-cms-path` on the element that shows a field or a record) and `resolveFieldPath`, the one rule of where a link may lead (`link-addresses.ts`), and the attributes a site puts on what it hides and shows itself (`reveal-markers.ts`). Formatted text (`rich-text.ts`) is data, never HTML: paragraphs and lists of pieces with `bold`, `italic` and `href` (checked by the rule of links), read in one normal form (empty pieces left out, neighbors with the same marks joined); a plain string is read as paragraphs, and `inline` keeps one paragraph. `components/RichText.astro` renders it with the site's own elements. A photo may carry a `focus` (0 to 1 from the left and the top), which `imagePosition` turns into `object-position`. `presets.ts` holds the sets of fields almost every site has (`seoFields`, `contactsFields`, `openingHoursField`), plain groups and collections of the usual fields. Every record of a collection has an `id` (`record-ids.ts`): `parseContent` keeps a valid one and never makes one up, so it gives the same content for the same input; `withRecordIds` gives ids to records without one (the CMS does it when it loads and saves), and `newRecord` starts a record with one. References are checked against the whole content after the fields (`reference-checks.ts`): an id its collection does not have is kept with the issue `missing-record`. Plain data that survives JSON, pure TypeScript: sites render with it, and the CMS checks and stores content with the same code (`@seamlet/astro/schema`).
  - `src/bridge` — the bridge on a site's preview. `connectToEditor({ editorOrigin })` does nothing outside a frame, says `ready` with its `PROTOCOL_VERSION` and, once the editor connects with the schema, reports where the marked elements are, what a person does, types texts in place and renders the editor's drafts. `page-reveals.ts` opens what hides a field: a click on the summary of a `<details>` opens it, a click on a radio button or a checkbox (or its label) flips it, so tabs and filters made with CSS work, the field the editor scrolls to has every `<details>` and `data-cms-reveal` part around it opened, and what was opened or flipped is opened or flipped again in a page rendered anew. `messages.ts` is the one description of what the bridge and the editor say to each other with `postMessage`; each side reads what it gets into those types and drops the rest, and hears only the other's window and origin. `PROTOCOL_VERSION` is raised whenever a message changes in a way the other side cannot read: sites update the package when they like, so the editor meets bridges of other versions.
  - `src/protocol.ts` — what the CMS's editor needs to speak to the bridge (`@seamlet/astro/protocol`): the messages, their readers and the rules both sides share. `@seamlet/astro/bridge` also gives `connectPage`, for the editor's tests.
  - `src/index.ts` — the integration `seamlet()`: it reads the site's `seamlet.json` (`site-config-file.ts`; `CMS_ORIGIN` of the environment takes the place of its `cms`, for a build for another CMS) and gives the site's build virtual modules (`virtual:seamlet/config` with the site's id, its title and the CMS's origin, `virtual:seamlet/site`, the site's module `src/seamlet.ts`), the preview (`/preview/[...page]`, `routes/preview.astro`, with `preview-requests.ts`: `GET` with the published content, `POST` with a JSON draft no bigger than 1 MB; `frame-ancestors` of the CMS, `noindex`, `no-store`) and the photos taken from the CMS (`/media/[site]/[file]`), both rendered on request; after a build it copies the uploaded photos the built pages refer to into the client output (`uploaded-photos.ts`), for a static host. The bridge goes on every page as a tiny script (`client.ts`) that loads the bridge only on `/preview` in a frame: a script of the injected route would be left out of a static site's on-demand pages.
  - `seamlet.json` at a site's root (`SITE_CONFIG_FILE`, read by `readSiteConfig` of `src/schema/site-config.ts`): what is known of a site before it is built, its id in the CMS (`isSiteId`, the one rule of an id, which also names the host of its preview), its title and the origin of its CMS. The CMS reads the same file from the site's repository, so the id is written once.
  - `src/cli.ts` — the package's command (`bin`), `npx @seamlet/astro init` (`src/init`): writes `seamlet.json` and the smallest site module the CMS edits (`site-files.ts`: a schema with one text, `src/seamlet.ts`, a page component), each only where the site has none (`write-site-files.ts`); the id comes from `--id` or the name in `package.json` (`siteIdOf`), and it prints what to do next (`astro add @seamlet/astro node`, a page that renders the content).
  - `src/site.ts` — `defineSeamletSite({ schema, initialContent, pages, photos })`, a site's one module, its id and title taken from `seamlet.json` (a page is its title for the editor, its component and where its search texts are), with `pageAt`, `loadPublishedContent`, `ownPhotoAt` (the image of the site's own photo at an address its content gives it, found by `photos`) and `description`, what the site tells the CMS about itself (`site-descriptions.ts`), handed out at `/seamlet/site.json` (`SITE_DESCRIPTION_PATH`, `routes/site-description.ts`) and read by the CMS with `readSiteDescription` (`src/schema/site-description.ts`, with `readFields`, a schema read back from JSON): the CMS keeps no copy of a site's schema.
  - `src/own-photos.ts` — the one rule of the site's own photos (an address of the site that is not an upload of the CMS) and where the site hands them out for the CMS's editor (`/seamlet-photos/<address>`, `routes/own-photos.ts`, a redirect to the build's file of the photo); `@seamlet/astro/protocol` gives it to the CMS.
  - Its README is what a site's author reads.
- `examples/coffee-shop` — the test site, connected the way every site is: it takes `@seamlet/astro` from the workspace as an installed package, so it checks the package as a site uses it. Its `Dockerfile` builds it for a server.

Boundaries, enforced by ESLint: `src/schema` imports nothing outside itself; `src/bridge` imports only `src/schema`; examples take only `@seamlet/astro`.

A site never renders content as raw HTML (`set:html`): the CMS's editor acts on what the preview says.

## Public API

- The package is public: a change of the schema language, of the messages or of what the integration adds is a change of its API, and it gets a version of the package (semver).
- A change of the messages the other side cannot read raises `PROTOCOL_VERSION`: sites update the package when they like, so the CMS's editor meets bridges of other versions.
- Commits follow Conventional Commits.

## Commands

- `make check` — the package's build, formatting check, types (`tsc` for the package, `astro check` for the examples), ESLint, Vitest, the examples' build. It must pass before a commit.
- `npm run dev:coffee-shop` — the test site on http://localhost:4322, its content from `CMS_ORIGIN` (`http://localhost:4321` by default).
- `npm pack --workspace @seamlet/astro` — what would be published. A release: raise `version` in `packages/astro/package.json`, merge, run «Publish @seamlet/astro» from the Actions tab (`.github/workflows/publish-astro.yml`: a version already on npm is refused, the published one is tagged `astro-v<version>`; npm trusts the workflow itself, run in the `npm` environment, with no token: trusted publishing).
